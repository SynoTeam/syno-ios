# iCloud 동기화 켜기/끄기 기술 검증 (#136)

검증일: 2026-11-13

## 결론

**실제 기기 간 동작은 확인하지 못했다.** 시뮬레이터에서 Apple 계정 로그인이 실패했고(iOS 26.2, "사용자 이름 또는 암호가 올바르지 않음", "네트워크에 연결할 수 없음"), 실기기에는 App Store판 데이터가 있어 Xcode 빌드를 설치하지 않았다.

그래서 구현은 확인된 사실만 약속하도록 보수적으로 한다.

- 설정은 **다음 실행부터 적용**한다. 실행 중에 저장소를 바꿔 열지 않는다.
- 화면 문구에 "다시 켜면 그동안의 변경이 동기화됩니다" 같은 확인되지 않은 동작을 넣지 않는다.
- 아래 "남은 확인"을 TestFlight 단계에서 확인한다.

## 확인할 질문과 현재 판단

| 질문 | 판단 | 근거 |
|---|---|---|
| 끈 동안 만든·고친·지운 데이터가 다시 켜면 iCloud로 올라가는가 | 올라갈 가능성이 높음 (미확인) | 아래 "근거" 참고 |
| 다시 켤 때 데이터가 중복되는가 | 중복되지 않을 가능성이 높음 (미확인) | 레코드는 객체마다 저장소에 기록된 CloudKit 레코드 이름으로 맞춘다. 끄고 켜도 같은 저장소 파일이라 이 기록이 남는다 |
| 앱을 다시 시작하지 않고 적용할 수 있는가 | 하지 않음 | `ModelContainer`를 앱 실행 중에 바꾸면 모든 저장소·서비스를 다시 만들어야 하고, 열린 화면이 이전 컨텍스트를 들고 있다. 위험에 비해 얻는 것이 작다 |

## 근거

공유 확장은 이미 **CloudKit 없이 같은 저장소 파일에 노트를 저장**하고 있다.

- `SynoShareExtension.entitlements`에 iCloud 권한이 없어서, 확장의 `ModelConfiguration` 기본값(`.automatic`)은 CloudKit 없이 열린다.
- 확장에서 저장한 노트는 다음에 앱을 열 때 iCloud로 올라가는 것을 전제로 출시 앱이 동작하고 있다. 다만 다른 기기 반영은 이번에 따로 확인하지 않았다.

동기화를 끈 동안의 변경도 같은 방식이다. 저장소를 CloudKit 없이 열어 변경을 남기고, 다음에 CloudKit과 함께 열 때 변경 기록(persistent history)을 보고 올린다.

## 남은 위험

- 끈 기간이 길어 변경 기록이 정리(truncate)되면, 다시 켤 때 전체를 다시 맞추는 과정이 생길 수 있다. 이때 시간이 오래 걸리거나 중복이 생기는지 확인하지 못했다.
- 동기화를 끈 상태에서 "데이터 초기화"를 하면 이 기기에서만 지워진다. 다시 켜면 삭제 기록이 올라가는지, iCloud의 데이터가 다시 내려오는지 확인하지 못했다. 초기화 경고 문구는 동기화가 켜진 경우를 기준으로 쓰여 있다.
- 끈 상태에서도 다른 기기는 계속 동기화하므로, 다시 켜면 양쪽 변경이 합쳐진다. 같은 노트를 양쪽에서 고쳤다면 마지막에 저장된 값이 남는다(CloudKit 기본 동작).

## 남은 확인 (TestFlight)

기기 두 대 또는 기기와 CloudKit Console(Development는 Xcode 빌드, Production은 TestFlight)로 확인한다.

1. 둘 다 켬: A에서 쓴 노트가 B에 보인다.
2. A를 끄고 다시 시작: A에서 노트 추가·수정·삭제 → B에 반영되지 않는다.
3. A를 다시 켜고 다시 시작: 2단계 변경이 B에 반영되고, 같은 노트가 두 번 생기지 않는다.
4. 각 단계에서 Xcode 콘솔의 `CoreData+CloudKit` 로그에 `truncated`, `reset` 같은 전체 재동기화 문구가 있는지 본다.

시뮬레이터 로그인이 되는 계정이 있으면, 시뮬레이터 1대와 CloudKit Console(Development, Private Database, `com.apple.coredata.cloudkit.zone`, `CD_StoredNote`)로도 1~3을 확인할 수 있다.
